### 问题列表

1. **思维链逻辑框重复**：第一个思维链框是空的，没有实际意义，直接使用了第二个思维链框
2. **回复内容包含 "data:" 前缀**：最终回答和思维链内容中显示了 "data:" 字样，不应该展示给用户
3. **缺少持久化**：逻辑链和回复内容需要保存到数据库，但目前没有实现持久化
4. **COT 和 TOT 模式都受影响**：两种思维链模式都存在以上问题

## 问题分析

### 问题 1：思维链框重复
- **原因**：前端代码在接收到流式数据时，可能创建了多个思维链容器
- **位置**：`chat.html` 中的 SSE 数据处理逻辑
- **修复方案**：确保只创建一个思维链容器，检查容器是否已存在

### 问题 2：显示 "data:" 前缀
- **原因**：前端在解析 SSE 数据时，没有完全剥离 `data:` 前缀，导致部分内容仍包含该前缀
- **位置**：`chat.html` 中的数据解析逻辑
- **修复方案**：在提取数据后，进一步检查并移除内容中的 `data:` 前缀

### 问题 3：缺少持久化
- **原因**：流式输出完成后，只保存了最终回答，没有保存思维链内容
- **位置**：`MessageController.java` 和 `StreamingChatService.java`
- **修复方案**：
  - 修改 Message 实体，添加思维链内容字段
  - 在流式输出完成后，同时保存思维链内容和最终回答
  - 更新数据库表结构

### 问题 4：COT 和 TOT 模式
- 两种模式使用相同的标记和处理逻辑
- 修复方案需要同时适用于两种模式

## 修复计划

### 第一步：修复前端显示问题
1. 移除重复的思维链容器创建逻辑
2. 清理数据中的 `data:` 前缀
3. 优化 SSE 数据解析逻辑

### 第二步：实现持久化
1. 修改 Message 实体类，添加 `thinkingContent` 字段
2. 更新数据库 Schema
3. 修改后端保存逻辑
4. 修改前端显示逻辑以支持显示历史思维链内容

### 第三步：测试验证
1. 测试 COT 模式
2. 测试 TOT 模式
3. 验证持久化功能
4. 验证历史消息显示

## 技术要点

- **SSE 格式**：Spring Boot 自动生成 `data:` 前缀（无空格）
- **流式输出**：使用 Reactor Flux 处理异步流
- **标记系统**：使用 XML 标签 `<think>`, `</think>`, `<answer>`, `</answer>`
- **前端缓冲**：使用 `markerBuffer` 处理标记被拆分的情况
