# 流式输出问题修复记录

## 问题描述

**日期**: 2026-05-09  
**模块**: virtual-chat - COT/TOT 思维链模式流式输出

### 症状
1. 后端控制台正常输出 AI 响应内容
2. 前端页面没有显示任何内容
3. 浏览器控制台显示接收到的 SSE 数据中 `data:` 后面是空的

### 用户反馈
> "仍然有问题，页面依然没有内容；浏览器控制台输出的data是空，是不是说明交互的数据格式不对或则解析的有异常"

---

## 问题分析

### 根本原因
`chatModel.stream()` 返回的是 `Flux<String>`，但代码错误地尝试按 `ChatResponse` 对象处理。

### 错误尝试历程

#### 尝试 1: 直接调用 getResult()
```java
return chatModel.stream(fullPrompt)
    .filter(r -> r != null && r.getResult() != null)
    .map(r -> r.getResult().getOutput().getText());
```
**错误**: `The method getResult() is undefined for the type String`

#### 尝试 2: 创建 Prompt 对象
```java
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.ai.chat.messages.UserMessage;

Prompt prompt = new Prompt(new UserMessage(fullPrompt));
return chatModel.stream(prompt)
    .filter(r -> r != null && r.getResult() != null)
    .map(r -> r.getResult().getOutput().getText());
```
**错误**: 编译失败，类型不匹配

#### 尝试 3: 使用 DashScopeChatOptions
```java
import com.alibaba.cloud.ai.dashscope.chat.DashScopeChatOptions;

DashScopeChatOptions options = DashScopeChatOptions.builder()
    .withTopP(0.7)
    .withTemperature(0.8)
    .build();

Prompt prompt = new Prompt(new UserMessage(fullPrompt), options);
return chatModel.stream(prompt)
    .filter(r -> r != null && r.getResult() != null)
    .map(r -> r.getResult().getOutput().getText());
```
**错误**: 仍然无法正确推断类型

## 最终解决方案

### 关键发现
通过参考 fileAgent 项目的正确用法，发现：
- `chatModel.call(String)` 返回 `String`（同步调用）
- `chatModel.stream(String)` 返回 `Flux<String>`（流式调用）

**不需要创建 Prompt 对象！** 直接传入 String 即可。

### 修复步骤

#### 步骤 1: 修复数据类型处理

**文件**: `src/main/java/com/virtualchat/service/StreamingChatService.java`

```java
// 直接流式输出 AI 响应（思维链模式下 AI 会按 prompt 要求输出标记）
System.out.println("[流式聊天] 准备发送Prompt，长度: " + fullPrompt.length());

return chatModel.stream(fullPrompt)
    .doOnNext(text -> System.out.println("[流式聊天] AI输出chunk: " + text.substring(0, Math.min(50, text.length()))))
    .filter(t -> t != null && !t.trim().isEmpty());
```

#### 步骤 2: 修改提示词，让 AI 输出标记

前端期望接收的标记格式：
- `[THINKING_START]` - 思维过程开始
- `[THINKING_END]` - 思维过程结束
- `[ANSWER_START]` - 最终答案开始
- `[ANSWER_END]` - 最终答案结束

**COT 模式提示词**：
```java
fullPrompt += "\n\n【重要】请严格按照以下格式输出：\n" +
             "1. 首先输出 [THINKING_START]\n" +
             "2. 然后展示你的逐步思考过程（思维链）\n" +
             "3. 输出 [THINKING_END]\n" +
             "4. 输出 [ANSWER_START]\n" +
             "5. 给出简洁的最终回答\n" +
             "6. 输出 [ANSWER_END]\n" +
             "\n示例：\n" +
             "[THINKING_START]\n" +
             "让我来分析这个问题...首先...其次...\n" +
             "[THINKING_END]\n" +
             "[ANSWER_START]\n" +
             "这是最终答案。\n" +
             "[ANSWER_END]";
```

**TOT 模式提示词**：
```java
fullPrompt += "\n\n【重要】请严格按照以下格式输出：\n" +
             "1. 首先输出 [THINKING_START]\n" +
             "2. 然后展示你的多种思路和方案比较（思维树）\n" +
             "3. 输出 [THINKING_END]\n" +
             "4. 输出 [ANSWER_START]\n" +
             "5. 给出最佳方案的简洁回答\n" +
             "6. 输出 [ANSWER_END]\n" +
             "\n示例：\n" +
             "[THINKING_START]\n" +
             "方案A:... 方案B:... 方案C:... 经过比较，方案B最优...\n" +
             "[THINKING_END]\n" +
             "[ANSWER_START]\n" +
             "基于方案B的最终答案。\n" +
             "[ANSWER_END]";
```

## 经验总结

1. **API 理解要准确**: 不同模型的 stream() 方法返回值可能不同
   - OpenAI: `Flux<ChatResponse>`
   - DashScope: `Flux<String>` （当传入 String 时）

2. **参考项目很重要**: fileAgent 项目提供了正确的用法示例

3. **调试日志很关键**: 添加详细的日志输出帮助定位问题

4. **Maven 编译问题**: JAR 文件被锁定时需要先终止 Java 进程

5. **前后端数据格式对齐**: 
   - 前端期望接收特定的标记格式（`[THINKING_START]` 等）
   - 后端需要通过提示词引导 AI 输出这些标记
   - 不能依赖后端自动添加标记，应该在提示词中明确要求

6. **SSE 数据格式**:
   - 后端发送: `"data: " + chunk + "\n\n"`
   - 前端解析: 按 `\n\n` 分割，提取 `data: ` 后的内容
