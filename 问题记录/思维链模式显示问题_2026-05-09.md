# 思维链模式显示问题修复记录

**日期**: 2026-05-09

## 问题描述

从用户提供的截图可以看到以下问题：

### 问题1：思维链逻辑框重复
- **现象**: 第一个思维链框是空的，没有任何内容，第二个框才显示实际内容
- **影响**: 用户看到两个思维链框，第一个是多余的
- **原因**: 前端代码中重复创建了思维链容器，在sendMessageStreaming函数中，isThinkingMode变量未定义，导致判断逻辑异常

### 问题2：回复内容包含"data:"前缀
- **现象**: 
  - 思维链内容显示为 `data:让我来分析这个问题...`
  - 最终回答显示为 `data:` 和 `data:那我们先确定在南京待几天呢?...`
- **影响**: 用户看到不应该看到的SSE协议前缀
- **原因**: SSE数据解析时没有正确处理`data:`前缀，Spring Boot的SSE格式是`data:`（无空格）

### 问题3：逻辑链和回复内容未持久化
- **现象**: 思维链推理过程和最终回答没有被保存到数据库
- **影响**: 刷新页面或重新加载后，历史对话的思维链内容丢失
- **原因**: Message实体缺少thinkingContent字段，前后端都没有处理这个字段

### 问题4：COT和TOT模式都需要修复
- 两种思维链模式都存在上述所有问题

## 修复方案

### 修复1：思维链框重复
**文件**: `src/main/resources/templates/chat.html`

**问题**: `sendMessageStreaming` 函数中使用了 `isThinkingMode` 变量，但该变量未定义

**修复**: 在函数开始处添加变量定义
```javascript
// 判断是否为思维链模式
const isThinkingMode = thinkingChainMode === 'COT' || thinkingChainMode === 'TOT';
```

### 修复2：清理"data:"前缀
**文件**: `src/main/resources/templates/chat.html`

**修复位置**:
1. 处理标记前的内容时：`beforeMarker.replace(/^data:\s*/g, '')`
2. 追加普通内容时：`markerBuffer.replace(/^data:\s*/g, '')`

在所有内容添加到thinkingContent和answerContent之前，都添加清理逻辑。

### 修复3：实现持久化

**数据库层**:
- **文件**: `src/main/java/com/virtualchat/model/Message.java`
- **修改**: 添加 `thinkingContent` 字段
```java
@Column(name = "thinking_content", columnDefinition = "TEXT")
private String thinkingContent; // 思维链内容（COT/TOT模式）
```

**后端层**:
- **文件**: `src/main/java/com/virtualchat/controller/MessageController.java`
- **修改**: 在保存消息时接收并保存thinkingContent
```java
// 如果有思维链内容，也保存
if (request.containsKey("thinkingContent")) {
    aiMessage.setThinkingContent((String) request.get("thinkingContent"));
}
```

**前端层**:
- **文件**: `src/main/resources/templates/chat.html`
- **修改1**: `saveAIMessage` 函数接收thinkingContent参数并传递给后端
- **修改2**: `loadMessages` 函数显示历史消息时，如果有thinkingContent则展示思维链UI

### 修复4：COT和TOT统一处理
- 两种模式使用相同的前端处理逻辑
- 两种模式都传递thinkingContent到后端
- 两种模式都保存到数据库

### 技术细节
1. **SSE格式**: Spring Boot自动生成 `data:` 前缀（无空格）
2. **流式输出**: 使用Reactor Flux处理异步流
3. **标记系统**: 使用XML标签 `<thinking>`, `</thinking>`, `<answer>`, `</answer>`
4. **前端缓冲**: 使用 `markerBuffer` 处理标记被拆分的情况
5. **数据库迁移**: Hibernate自动添加thinking_content列
